# Формат .als — что выяснено на реальной библиотеке

Проверено на Live 10/11/12, выборка — 427 сетов из `E:\Music\Ableton Projects`.

## Контейнер

`.als` — это **gzip поверх XML**, не tar. Магия `1F 8B`. Распаковка даёт один XML-документ:
типичный сет 100 КБ на диске разворачивается в ~2.9 МБ текста, то есть примерно 25×.

При тысяче с лишним сетов поднимать это целиком в память нельзя — разбор потоковый,
`XmlReader` прямо поверх `GZipStream`. Выходит около 150 мс на сет.

Корень несёт версию, которой сет сохраняли последний раз:

```xml
<Ableton MajorVersion="5" MinorVersion="12.0_12300" Creator="Ableton Live 12.3.5" ...>
```

## Треки и темп

Типы: `AudioTrack`, `MidiTrack`, `GroupTrack`, `ReturnTrack`, `PreHearTrack` и `MainTrack`.
**Внимание:** в Live 12 мастер-трек называется `MainTrack`, в более старых сетах — `MasterTrack`.
Читать надо оба имени.

Имя трека — `<Name><EffectiveName Value="..."/>`, темп — `<Tempo><Manual Value="111"/>` внутри
мастер-трека (узел `Tempo` встречается и в клипах, поэтому нужен именно тот, что в мастере).

## Плагины

| Узел | Что даёт |
|---|---|
| `VstPluginInfo` | `PlugName`, `UniqueId` и **полный путь к .dll** |
| `Vst3PluginInfo` | `Name` и `Uid` из четырёх полей; пути нет |
| `AuPluginInfo` | macOS |
| `MxDevice*` | Max for Live, файл `.amxd` приходит через вложенный `FileRef` |

Путь к `.dll` у VST2 — единственный случай, когда прямо из сета видно, откуда плагин
загружался. У VST3 остаётся только имя и Uid.

Ловушка: внутри `Vst3PluginInfo` есть пустой `<Name Value="" />` в блоке пресета, а настоящее
имя — прямой потомок узла плагина. Разбирать надо с учётом глубины, иначе имена теряются.

## Какие плагины стоят на машине

`%APPDATA%\Ableton\Live <версия>\Preferences\PluginScanDb.txt` — база самой Live,
переписывается при каждом её запуске. Обычный текст, три таблицы:

```
Logging plugins information about plugin modules start
ModuleId,Path,Arch,Processor,ScanState,Fingerprint
889,"C:\Program Files\Common Files\VST3\Serum2.vst3",3,1,ok,"1258800:6a4ca126"

Logging plugins information about all plugins start
PluginId,ModuleId,DevIdentifier,Name,Vendor,Version,SdkVersion,Flags,ScanState,SubCategories,IsEnabled
1698,889,"device:vst3:instr:56534558-…","Serum 2","Xfer Records","2.1.5","VST 3.7.12",1,1,"Instrument|Synth",1
```

Сканировать папки самим не нужно: пришлось бы разбирать бинарники VST, а Live это уже
сделала — и ровно с теми настройками папок, которые в ней стоят.

Есть и `PluginScanner.txt`, но это **лог**, а не база: в нём только те плагины, которые
сканировались заново, остальные помечаются как «plugin already scanned» без подробностей.
Полный список — только в `PluginScanDb.txt`.

**Опознание.** По идентификатору, а не по имени:

| Формат | В базе Live | В сете |
|---|---|---|
| VST3 | `device:vst3:instr:ed57bd72-5c60-467e-a64d-d2f400758b6f` | `<Uid><Fields.0..3/>` — те же 16 байт четырьмя int со старшего байта |
| VST2 | `device:vst:instr:2017543218?n=…` | `<UniqueId Value="2017543218"/>` |

Проверено на FabFilter Pro-Q 4: Fields «-313016974, 1549813374, -1504849164, 7703407»
дают ровно `ed57bd72-5c60-467e-a64d-d2f400758b6f` из базы.

**Ловушки.**

* `.vst3` у новых плагинов — **папка-бандл**, а не файл: `File.Exists` на установленном
  Serum 2 честно вернёт false, проверять надо и `Directory.Exists`.
* Один плагин попадает в базу несколько раз, если Live видит несколько его файлов
  (Debug и Release одной сборки) — считать за один.
* Один и тот же плагин заведён и как VST2, и как VST3 с разными идентификаторами.
  Сет, сохранённый с VST2-версией, при установленной VST3 всё равно откроется с дырой,
  поэтому это отдельное состояние, а не «установлен».

## Тональность проекта

Общая тональность (Live 12) лежит прямо в `LiveSet`:

```xml
<ScaleInformation>
    <Root Value="0" />   <!-- 0 = C ... 11 = B -->
    <Name Value="0" />   <!-- индекс лада -->
</ScaleInformation>
<PreferFlatRootNote Value="false" />
```

Такой же узел есть **у каждого клипа**, поэтому брать надо именно тот, что лежит прямо
в `LiveSet`, иначе прилетит тональность случайного клипа.

Порядок ладов не угадан: он вшит в `Ableton Live 12 Suite.exe` вместе с документацией LOM,
где перечислены «default scale names that can be saved with a set and recalled» — от
`Major` и `Minor` до `Messiaen 7`, всего 35 штук. Оттуда же подтверждение про ноты:
«The root can be a number between 0 and 11, with 0 corresponding to C».

У сетов из Live 9/10/11 узла нет — тональность просто пустая.

## Пустой сет

`Resources\Builtin\Templates\DefaultLiveSet.als` в установке Live — тот самый файл, из
которого Live делает новый проект: 120 BPM, 2 MIDI + 2 audio трека, 2 return, ноль
плагинов. Копировать его надёжнее, чем собирать XML руками: схема гарантированно та,
которую понимает установленная версия.

## Аранжировка: клипы на линейке

Клипы линейки лежат внутри дорожки по пути `DeviceChain → MainSequencer → Sample`
(у аудио) или `ClipTimeable` (у midi), дальше **`ArrangerAutomation → Events`**:

```xml
<AudioClip Id="3" Time="96">
    <CurrentStart Value="96" />        <!-- доли от начала сета -->
    <CurrentEnd Value="128" />
    <Loop>
        <LoopStart Value="0" />        <!-- при выключенной петле это старт/энд-маркеры, -->
        <LoopEnd Value="32" />         <!-- а сама петля уезжает в HiddenLoop* -->
        <StartRelative Value="0" />
        <LoopOn Value="false" />
    </Loop>
    <Name Value="den 97 trashcore" />
    <Color Value="23" />
    <Disabled Value="false" />
</AudioClip>
```

**Ловушка:** такие же `AudioClip`/`MidiClip` лежат в `ClipSlotList` — это клипы сессии,
на линейке их нет. Различать можно только по тому, находимся ли мы внутри
`ArrangerAutomation`.

Ноты у midi-клипа:

```xml
<Notes><KeyTracks><KeyTrack Id="19">
    <Notes><MidiNoteEvent Time="0" Duration="32" Velocity="95" /></Notes>
    <MidiKey Value="26" />          <!-- высота приходит ПОСЛЕ самих нот -->
</KeyTrack></KeyTracks></Notes>
```

`Time` у ноты — от начала содержимого клипа, а не сета. Момент на линейке:
`CurrentStart + (Time − LoopStart − StartRelative) + k·(LoopEnd − LoopStart)`,
где k — номер повтора петли (только при `LoopOn`).

## Цвета

Палитра клипов и дорожек — 70 цветов, сетка 14×5, та же, что в контекстном меню трека.
Значений в установке Live нет: они зашиты в бинарник, в темах (`Resources/Themes/*.ask`)
лежат только `Clip1..Clip16` — это старая палитра из 14 цветов, не она.

Что при этом **есть** в установке — таблица `live_to_push2_colors` в
`Program\Push2\qml\Ableton\Push\Assets\css\dark.css`: соответствие всех 70 индексов Live
цветам экрана Push, ровно пятью строками по 14. По ней проверены и число цветов, и
порядок оттенков в строке.

Нумерация зависит от версии:

| Версия | Узел | Значение |
|---|---|---|
| 11, 12 | `Color` | прямо индекс палитры, 0..69 |
| ≤ 10 | `ColorIndex` | у клипов — индекс палитры; у дорожек смещён |

Смещение у дорожек проверено на 4300 парах «дорожка и её клипы» из старых сетов:
в 85% случаев ровно **140** (остальное — клипы, которым цвет меняли руками), отдельным
блоком встречается **218** (дорожка 282 при клипах 64). Если номер не попал ни в один
блок, цвет дорожки берётся как самый частый цвет её клипов — клип по умолчанию
наследует цвет дорожки.

## Ссылки на файлы — самое важное

### Зависимость это только сэмпл клипа

`FileRef` встречается в сете под самыми разными узлами, но **потерянным файлом Ableton
считает лишь сэмпл клипа** — тот, чей прямой родитель `SampleRef`. Всё остальное — это
происхождение встроенного содержимого: пресет или рэк Ableton хранит прямо внутри сета,
и `FileRef` рядом с ним лишь помнит, откуда его перетащили. Файл для открытия не нужен, и
Ableton на его отсутствие не жалуется.

| Родитель `FileRef` | Что это | Считать? |
|---|---|---|
| `SampleRef` | аудио клипа | **да** |
| `FilePresetRef` | откуда взят пресет устройства | нет |
| `AbletonDefaultPresetRef` | дефолтный пресет устройства | нет |
| `OriginalFileRef` | исходник до конвертации/анализа | нет |
| `MxPatchRef`, `MxDPatchRef` | внутренние патчи Max | нет |

Проверено на выборке в 184 сета: у провенанс-узлов «отсутствует» **94%**
(`AbletonDefaultPresetRef`) и **87%** (`FilePresetRef`) путей — они ведут на чужую машину
(`C:/Users/ivani/...`), потому что содержимое давно в сете. Считать их потерями — тот
самый баг, который видно глазом: Ableton открывает проект молча, а менеджер писал «2
missing». После сужения до `SampleRef` три таких сета показали ровно 0 потерь, как в Live.

### RelativePathType — корень пути

Ключевое поле у сэмпла — `RelativePathType`, оно задаёт **корень**, от которого считается
`RelativePath`:

| Тип | Корень | Пример |
|---|---|---|
| 0 | относительного корня нет — только абсолютный путь | `C:/.../loop.wav` |
| 1 | папка проекта, путь может уходить вверх | `../../Samples/pack/loop.wav` |
| 3 | внутри папки проекта | `Samples/Recorded/audio.wav` |
| 5 | корень Live Pack, имя в `LivePackName` | `Audio Effects/Spectral Blur` |
| 6 | User Library | `Presets/Audio Effects/EQ Eight/x.adv` |
| 7 | `Resources\Builtin` установленного Live | `Devices/Audio Effects/LFO/...` |

Тип 0 не значит «ссылки нет»: у сэмплов это чаще всего файл, перетащенный из-за пределов
папки проекта, — Ableton хранит его по абсолютному пути. В выборке type 0 у сэмплов это
25 тыс. `.wav` и 15 тыс. `.mp3`, и большинство находится. Пустая заглушка (оба пути
пустые) — отдельный случай, таких тоже много.

Абсолютный путь в `Path` — только подсказка, доверять ему нельзя:

* в проектах из коллабораций он ведёт в чужой профиль (`C:/Users/ivani/...`);
* в старых сетах — на прошлую версию (`.../Live 11.1.6 Suite/Resources/...`);
* паки могли переехать на другой диск.

Правильный порядок: сначала корень по `RelativePathType`, и лишь потом абсолютный путь как
запасной вариант.

## Где искать корни на текущей машине

`%APPDATA%\Ableton\Live <версия>\Preferences\Library.cfg` — обычный XML, содержит карту паков:

```xml
<LibrarySliceInfo Path="E:\Music\Factory Packs\Creative Extensions"
                  DisplayName="Creative Extensions" UniqueId="..." />
```

и расположение User Library через `ProjectPath` + `ProjectName`. Это единственный достоверный
источник: пути внутри сетов устаревают, а этот файл описывает текущее состояние машины.

## Результат на реальной библиотеке

Выборка 366 сетов, считаем только сэмплы клипов (`SampleRef`):

* 281 485 ссылок на сэмплы, из них 16 608 потеряны (5.9%)
* сетов с потерянными сэмплами — 211
* все 61 подключённый пак на месте

Для сравнения: если считать потерянным любой `FileRef` подряд (как было до правки),
получалось 289 сетов «с потерями» и 26 970 ссылок — то есть 78 сетов флагались зря
из-за путей к встроенным пресетам и рэкам.
